# updf MVP specification

## Purpose

updf is a learning and portfolio project: a minimal, well-built web PDF text editor. Success means a clean, working app built on free and open-source libraries only. The functionality is deliberately minimal.

## Scope

**In the MVP**
- Upload one PDF at a time from a dashboard, with no server storage.
- Add new text boxes anywhere on a page.
- Replace an existing line of text (cover the original and draw new text on top of it).
- Format each text box with font, size, bold, italic, underline, colour and alignment.
- Undo and redo, zoom, and page thumbnails.
- Autosave in the browser (survives a page reload).
- Download the edited PDF, generated by the .NET backend.
- English and Polish interface. Text content supports Latin (including Polish), Cyrillic and Greek.
- Light and dark themes.

**Out of the MVP (future)**
- Login, server-side storage and server-side autosave.
- Exclusive PDF sharing and PDF templates.
- True in-place text editing, and real removal of replaced text.
- Asynchronous (background job) processing.
- Automatic wrapping, mixing styles within one box, strikethrough, highlight, lists, rotated text.
- Unlocking password-protected PDFs, and page operations (rotate, reorder, delete, merge).
- Non-Latin, non-Cyrillic, non-Greek scripts (CJK, Arabic, Hebrew, right-to-left text).
- A list of recently opened documents.

## Key decisions

| Topic | Decision |
|---|---|
| Rendering and text detection | pdf.js (`pdfjs-dist`) in a Web Worker |
| Writing the PDF | Done on the backend with PDFsharp (MIT licence), in memory |
| Test-side PDF reading | PdfPig (backend tests); pdf.js in Node (Playwright) |
| Fonts | New text boxes: Noto Sans, Noto Serif and Noto Sans Mono. Replacements: the original embedded font while it has the characters, else a similar open font from `fonts/` (metric-compatible fonts for common proprietary ones, popular open families by name), else Noto. Regular, bold, italic and bold italic, embedded with only the used characters |
| Browser storage | IndexedDB behind a `DocumentRepository` interface |
| Interface languages | English and Polish. Defaults to the browser language, with a switcher and the choice remembered |
| Versions | The latest stable versions of every framework and library |

## Architecture

```
frontend/    Next.js app (dashboard, editor)
backend/     .NET solution: Updf.Api, Updf.Api.Tests
e2e/         Playwright suite
fonts/       Open TTF files (Noto plus the similar fonts, downloaded from Google Fonts), the single source used by both apps
docker-compose.yml
```

**Frontend**
- **Dashboard (`/`):** a drop zone and file picker. The browser checks the file (starts with `%PDF-`, is at most 25 MB and 100 pages, and isn't password-protected) before opening the editor. When an autosaved document exists, it shows a "Continue editing *name.pdf*" card.
- **Editor (`/edit`):** the page view, toolbar and formatting bar.
- **PDF renderer:** pdf.js in a Web Worker. It draws page images on demand, and groups existing text into lines with their position, size and font hint.
- **Editor state:** the document, the list of edits and the undo/redo history.
- **`DocumentRepository`:** saves and loads the original PDF bytes plus the edit list. The current implementation uses IndexedDB, and a server-backed implementation replaces it once login exists.
- **API client:** `exportPdf(file, edits)`.
- **Translations:** `en` and `pl` message files. All interface text goes through them.

**Backend**
- **`POST /api/pdf/export`:** builds the edited PDF.
- **`PdfValidator`:** repeats every upload check on the server.
- **`PdfEditor`:** applies the edits with PDFsharp, the fonts in `fonts/` and, for replacements, the PDF's own fonts.
- **`/health/live` and `/health/ready`:** health checks.
- **Nothing is persisted:** no database and no disk writes.

## Edit model

This contract is shared by the frontend, the backend and autosave. There's one edit type: a text box with an optional cover. A replacement is a text box with a cover.

```json
{
  "version": 1,
  "edits": [{
    "id": "uuid",
    "page": 0,
    "x": 72, "y": 96,
    "lines": ["Zażółć gęślą jaźń"],
    "style": { "font": "Noto Sans", "size": 12, "bold": false, "italic": false,
               "underline": false, "color": "#18181B", "align": "left" },
    "cover": { "x": 70, "y": 84, "width": 210, "height": 16, "color": "#FFFFFF" }
  }]
}
```

- **Coordinates:** in points (1/72 inch), measured from the top-left corner of the page as displayed (after cropping and rotation). The backend converts them to PDF page coordinates. `x`/`y` is the top-left of the text box, and `align` aligns lines within the box's width.
- **`page`:** zero-based.
- **`font`:** a font family in `fonts/`, such as `Noto Sans`.
- **`pdfFont`:** only on replacements: the name of the original font, and its bold and italic. The box is drawn in that font while all its characters are in it and bold and italic are unchanged. The export request adds each line's character codes in that font.
- **`size`:** 6–72 pt.
- **`color`:** `#RRGGBB`.
- **`cover`:** left out for new text boxes.
- **`version`:** allows the format to change without breaking documents that were autosaved earlier.
- **Limits:** at most 1000 edits per document and 100 lines per text box.
- **Line height:** the `font`'s own line spacing (ascent + descent + line gap), set explicitly in the preview, so preview and output match.

## Editor behaviour

**Layout**
- **Top bar:** file name, undo and redo, zoom, language switch, theme toggle, and Download (the only accent-coloured button).
- **Left:** a collapsible panel of page thumbnails.
- **Centre:** pages on the canvas background in a vertical scroll, drawn only as they come into view.
- **Formatting bar:** shown only while a text box is selected.

**Tools:** Select (the default) and Add text (shortcut `T`).

**Add text**
- Clicking a page creates an empty box in the style used last, ready to type.
- Enter starts a new line. There's no automatic wrapping.
- Esc or clicking outside finishes the edit. A box left empty is discarded.

**Replace text**
- In Select mode, hovering over an existing line shows a faint outline.
- Clicking a line creates a replacement for the whole line. The cover takes the line's area (with a small margin) and its colour from the pixels around the line in the page image.
- The box starts with the original text in the original font and size. Its font can't be changed. An underlined line starts underlined.
- Edited text in the original font keeps the PDF's kerning between letters (not next to spaces). Until the text or style changes, the line shows exactly as in the PDF (the box can't reproduce justified spacing or kerned spaces), and a replacement left unchanged is discarded when its edit finishes, leaving nothing to undo.
- The new text can be moved, but the cover stays over the original.
- Deleting a replacement brings the original line back.
- The first replacement in a session shows a one-time hint: "Replaced text is hidden, not removed. Don't use this to remove sensitive information."
- On scanned or image-only pages there's no text to replace. A hint says only adding text is available.

**Formatting** applies to the whole box: font (new boxes only), size, bold, italic, underline, colour (a preset palette plus a custom picker) and alignment.

**Boxes**
- Select with a click or Tab. Move by dragging or with the arrow keys. Delete with Delete.
- There's no resizing, because the box size follows its text.

**Undo and redo:** `Ctrl+Z` and `Ctrl+Shift+Z` (`Cmd` on macOS), and the top bar buttons. Each completed action is one step: create, finish an edit, change a style, move, delete. A new box and its text are one step, and so is any formatting done while typing. Arrow presses in a row on one box are one move. While typing, the shortcuts undo typing in the box.

**Zoom:** fits the page width by default, adjustable from 50% to 200% with the top bar, or with Ctrl+wheel and a trackpad pinch around the pointer (not the browser's zoom). A zoom change keeps the point it centres on in place.

**Autosave**
- The document and edits are saved one second after each change.
- Opening a different file asks for confirmation if a saved document would be replaced.

**Download**
- Shows a progress state, then saves `<name>-edited.pdf`.
- The edits remain, so the user can keep working.

**Small screens:** the app is designed for desktop first. On a phone or tablet the thumbnail panel collapses, and editing works with tap and the on-screen keyboard.

## API

`POST /api/pdf/export`
- **Request:** `multipart/form-data` with `file` (the original PDF) and `edits` (the JSON above).
- **Success:** `200 application/pdf` with `Content-Disposition: attachment; filename="<name>-edited.pdf"`.
- **Errors:** `ProblemDetails` with a stable `code` extension. The frontend translates each `code`, so the server never sends user-facing text.

| Status | `code` | When |
|---|---|---|
| 400 | `invalid-edits` | The edits fail the edit model's rules or limits, or `page` is out of range |
| 400 | `unsupported-characters` | Text uses characters the box's font can't show |
| 413 | `file-too-large` | File over 25 MB |
| 415 | `not-a-pdf` | File doesn't start with `%PDF-` |
| 422 | `pdf-encrypted` | Any encrypted PDF, including ones with only an owner (permissions) password, which PDFsharp cannot modify |
| 422 | `pdf-too-many-pages` | More than 100 pages |
| 422 | `pdf-unreadable` | Damaged or unparseable PDF |
| 429 | `rate-limited` | More than 10 exports per minute from one IP address |
| 503 | `processing-timeout` | Processing took longer than 30 s |
| 500 | `unexpected` | Anything else. The response includes a request ID, and details go to the server log |

**Server safeguards**
- Requests over 26 MB are refused before they're fully read.
- CORS allows only the frontend's origin.
- Exports run synchronously within the request, with a 30 s timeout.
- Logs never contain file contents or the text of edits.
- Embedded JavaScript and attachments in the original PDF are kept as they are, never run, and not removed. The output goes back only to the person who uploaded it. Removing them becomes a requirement once sharing exists.

## Error handling in the frontend

- **Upload check fails:** a translated message under the drop zone.
- **Unsupported characters:** a warning on the text box while typing. The frontend checks text against a list of supported characters taken from the fonts in `fonts/`, and the backend checks the actual fonts.
- **Export fails:** a banner with the translated message and a Retry button. Edits are never lost.
- **Autosave fails** (for example, browser storage is full): a non-blocking warning, "Autosave is off. Download to keep your work."

## Testing

**Backend (xUnit)**
- **Unit tests:**
  - `PdfValidator`: file signature, password protection, page limit, damaged files.
  - Checks on the edits.
  - Coordinate conversion for rotated and cropped pages.
  - `PdfEditor`, verified by reading the output back with PdfPig: the text is present, Polish characters survive the round trip, and the fonts are embedded.
- **Integration tests** (`WebApplicationFactory`): every row of the error table returns its status and `code`.

**Frontend (Vitest)**
- Unit tests for:
  - Editor state: add, move, style, delete, undo, redo.
  - Grouping text into lines.
  - Sampling the cover colour.
  - Coordinate conversion.
  - `DocumentRepository`, using an in-memory stand-in for IndexedDB.
- A check that every `en` message key exists in `pl`.

**End-to-end (Playwright, against the `docker compose` stack)**
- **Upload:** a valid PDF opens the editor. A non-PDF, a file over 25 MB, a password-protected file and a 101-page file are each rejected with the right message.
- **Add text:** with every style option. Download, read the PDF back and check the text, including Polish characters.
- **Replace a line:** download and check the new text is present. A screenshot comparison confirms the original is covered.
- **Editing:** moving, deleting (which brings the original back), undo and redo.
- **Autosave:** after a reload, "Continue editing" restores the document and edits.
- **Interface:** switching to Polish, and the theme toggle.
- **Export failure:** shows the Retry banner. This is the only place a network failure is simulated.
- **Everywhere:** screenshot comparisons in both themes and axe accessibility checks, run in Chromium, Firefox, WebKit and a mobile viewport.

**Test PDFs** (shared by all suites): simple text, 100 pages, 101 pages, password-protected, scanned, a rotated page, a cropped page, Polish text, a damaged file, a coloured background, and a file that isn't a PDF. The file over 25 MB is generated when the tests run.
